## 1. 目标与范围

普通和 RAG 工作台均支持同题并行连续对话、刷新恢复、各模型独立的有界上下文、自动压缩、来源可追溯的关键记忆、后台评分与会话报告。RAG 每轮独立改写检索问题、检索新证据，支持历史引用回溯及知识库版本变化检测。

首版不支持编辑历史、分叉、会话中途更换候选模型/知识库/生成参数，不实现自动出题、跨会话记忆或新向量记忆库。技术限额、单消息长度和费用不能被“长对话”绕过；不承诺无损无限记忆。

架构：复用现有 ModelClient、普通/RAG 检索和计费基础；增加会话协调层、上下文构建模块和共用多轮评分模块。FastAPI、SQLAlchemy/Alembic、现有后台执行设施、React/TypeScript；不引入新的 Agent 框架。

## 2. 不变量

1. 用户问题每轮共享；模型 A 只能使用 A 的历史回答和检索证据。所有历史由服务端加载，客户端不可提供可信历史。
2. 会话固定所有者、模式、候选配置快照、评审配置、思考模式、压缩策略和 RAG 知识库版本；不保存明文 API Key。运行时重新鉴权配置可用性，停用模型不能通过快照绕过。
3. 同一会话只能有一轮生成中；评分不占用生成锁。请求幂等键和预期轮次同时防止重复提交和跨标签页竞争。
4. 只有完整成功回答进入后续上下文。失败分支可在下一轮开始前重试或明确跳过；重试保留尝试和费用，不覆盖成功分支。下一轮开始后禁止改写其祖先。
5. 会话公开/私有统一控制所有轮次与报告。公开仅赋予读取权，不赋予续聊、复评或访问源知识库权限。新会话默认私有，旧记录不批量改权限。
6. 每轮输入、输出、压缩与评审保留版本和费用快照；评分只使用截至该轮的材料，禁止未来信息泄漏。
7. 摘要、用户内容、模型历史、文档和评审材料都是不可信数据，不可升级为系统指令。
8. 不适用、无法判断、调用失败三者分离，不能把缺证据重新归一化成高分。

## 3. 上下文与自动压缩

### 3.1 数据构成

`系统规则 + 有来源的结构化记忆 + 较早历史摘要 + 最近完整对话 + 本轮问题 + 本轮 RAG 证据`。

原始消息始终持久化。消息保存角色、模型分支、轮次；历史思考内容不作为普通上下文重复传输。结构化记忆记录用户目标、事实、有效约束、修正、待办及模型建议，区分用户确认事实与未经确认的模型结论。每项保存来源消息/原文、适用范围、替代关系。

### 3.2 预算

增加管理员可维护的上下文容量配置，不能凭模型名称猜测。输入上限为共同上下文容量减各分支输出预留与协议安全余量，RAG 证据和当前问题也计入预算。模型配置未知容量时使用明确展示的保守配置并允许管理员修正。

优先复用可用 tokenizer；无精确 tokenizer 时采用保守估计并标明 estimated，不使用字符数等于实际 Token 的假设。默认达到可用输入预算 75% 触发压缩，目标不高于 55%，最近原文预算优先保留；压缩后重新验证上限。

压缩由固定摘要模型执行，候选分支独立；只压缩完整较早轮次，不裁切半条消息。返回结构化摘要、关键记忆及原文来源；校验未知来源、空结果、超预算、关键项缺失后才提交新版本。失败保留旧版本：原文装得下则继续，否则标记上下文准备失败，不静默删除信息。单条当前问题/必要证据超限时明确拒绝并提示缩短输入。

当前内核采用 UTF-8 字节数加消息开销的保守估计。默认保留最近两个完整轮次；55% 是优化目标，必要记忆/近期原文占用使其无法达到时，只允许低于硬上限且确实缩小的结果，并返回 target_reached=false，不静默删去必需内容。内核校验摘要来源覆盖；关键事实语义校验和结构化记忆提取由后续模型执行模块实现。摘要模型默认使用评审模型；关闭评审且未指定摘要模型时固定首个候选配置，创建会话响应明确返回 summaryModelId。

摘要按覆盖轮次和来源哈希缓存，保留历史版本；在分段归并时回读来源原文，避免只对旧摘要反复概括。历史精确引用按消息 ID 回溯。压缩记录包含前后估计量、版本、费用、失败码。

## 4. RAG 多轮

RAG 存储复用原子轮次预先创建的 taskId：内部 create 可接收 reserved_turn_id，但必须匹配作者、当前生成中轮次、原问题、冻结候选与思考配置；已创建回答的任务不能重复初始化。初始化时比较知识库、文档与 Embedding 语义快照，证据固定屏障再次比较 Embedding 和索引版本。旧单轮接口不允许传入此内部参数。该存储能力已由内部多轮协调器调用，RAG 续聊 HTTP 接口已接入该协调器。

多轮 RAG 回答生成结束后独立结算检索/生成阶段，用现有 RAG 用量流水幂等入账；不运行旧单轮三次 Judge，也不写伪造质量分。成功回答可进入后续历史，新评分另存 conversation_assessments；要求提取/摘要/新 Judge 通过会话阶段流水计费，生成用量不能再次记入会话流水。整个轮次由会话协调器统一完成。

RAG 上下文按 rewrite/answer 两阶段分别构建：两者从本分支原始成功历史读取，answer 将本轮已固定 evidence 和问题一起计入硬预算，不能盲目复用改写阶段剩余额度。每阶段可独立压缩，费用分别使用 rewrite_summary/answer_summary；同一 ConversationContext 的 rag_requests 保存两份不可覆盖的实际 messages、准备哈希和压缩来源，缓存命中不再次摘要。这不是两次生成尝试，attempt 保持原值。历史精确引用回溯已由协调层接入，不能把历史答案当作本轮 evidence。

RAG 生成协调器先校验固定配置、知识版本与额度，再预留轮次、初始化原任务、提取共享要求，通过有界事件队列驱动独立检索/回答及结算；取消时先停止生产任务，再收尾 RAG 用量和会话锁。改写、Embedding、生成开始前分别检查当前账号与额度。内部生成验证可先独立运行，HTTP 开放仍以新 RAG 评分与证据回溯接通为前提。

每分支从当前问题和本分支记忆/近期历史生成可独立理解的检索问题，再复用权限过滤的检索流程。配置、检索预算一致；实际检索问题和证据可以不同。

历史引用使用稳定证据 ID（回答 ID + 原标签），展示标签仍可按本轮重新编号。用户追问某轮引用时只加载该分支实际引用的证据快照，重新检查所有者及当前知识库权限，再纳入本轮明确 evidence；历史回答/摘要不是知识证据。证据及对话分别组装和记录。评分资料保留 `historical_references` 数组（原轮次引用及稳定来源 ID），同一资料被多轮引用时保留全部对应关系；映射只从本轮实际回答请求快照读取并核对资料，不接受调用方自行指定。正式复评复用同一映射。

## 5. 评分契约

### 5.1 要求记录与检查项

用户要求在候选回答生成前提取，所有共享明确要求共用；指代模型建议时按各自分支解析。记录 id、内容、类型、sourceMessageId、原文片段、起止轮次、scope、supersedes、active/ambiguous 状态。只有明确强约束可标 critical，模型建议不能自动升级成要求。

评审检查项包含 id、dimension、requirementId（可空）、适用状态 applicable/not_applicable/unknown、rating（适用时为严格整数 0..4）、简短理由、原文证据列表、critical、passed（仅关键要求适用）。unknown 表示证据不足，必须保留且不能重分配其权重。

五档：0 完全失败，1 严重缺失，2 部分满足，3 基本满足，4 完整满足。检查项由共同要求和固定维度标准确定，复评不得重新生成检查项数量或权重来偏袒答案。重复 id、无来源证据、非有限分数、布尔冒充整数、超范围分数必须拒绝。

### 5.2 单轮对话分

维度：solution 40%、context 25%、instruction 20%、expression 15%。

`dimension = 10 * sum(rating) / (4 * applicable_count)`。

`dialogue = sum(dimension * weight) / sum(applicable_weight)`。

没有历史依赖时 context 可不适用；存在 unknown 的适用维度不给完整综合分。保留各已知维度和 coverage。关键要求失败独立返回 criticalPassed=false，排序先按关键要求状态分组，再按分数，不把部分维度的高分当作任务成功。安全问题作为带证据的发现单列，不由平均分掩盖。

coverage 定义为已知适用维度权重 / 排除 N/A 后的总权重；没有评价对象时为 0。缺少整个维度视为 unknown；同维度出现 unknown 时该维度分为空，不将其当零或排除刷分。正式复评各维度全为零仍可稳定通过；一致的关键要求失败仍是稳定成绩，只有判断冲突才算不稳定。

### 5.3 RAG 证据分

断言保存稳定 id、回答原文片段/位置、needsCitation、支持值 0/0.5/1（或 unknown）、实际引用关系、证据 id、理由。重复断言不重复计数，引用必须实际出现在候选回答中。已知引用与回答中实际出现但不存在于证据快照的错误引用分开保存：错误引用关系计零分，只有错误引用的断言引用覆盖为零；Judge 伪造回答中不存在的引用、将已有证据标成错误引用或同时放入两类集合时拒绝该次评审。支持判断指给定资料支持，不代表外部世界真值。

- faithfulness = 10 * 需要资料支持断言的支持值均值。
- citationCorrectness = 10 * 实际断言-引用关系的支持值均值。
- citationCompleteness = 10 * 需要资料支持断言中实际正确引用覆盖值均值。
- evidence = 0.50 * faithfulness + 0.30 * citationCorrectness + 0.20 * citationCompleteness，真正不适用维度重归一化；unknown 不归一化。
- 没有事实断言：证据组 not_applicable，仍评价对话；有断言却完全不引用：完整性为零，引用正确性不适用。证据不足合理拒答不作为编造。

证据 Judge 实现契约：服务端按回答的句末标点/换行建立带起止位置的固定片段，紧随句末的引用归入前句；相同片段去重。Judge 必须逐片段返回是否包含需资料支持的事实、整体支持档位、引用联合覆盖档位、每个已知引用的支持档位及对应资料逐字引文。片段可能含复合断言，部分内容支持只能给 0.5，不能宣称完成了语义原子断言拆解。片段集合、引用关系与资料快照在正式复评前冻结，Judge 不能省略不利片段或添加引用；实际未知引用由服务端解析并计零。正向支持必须提供资料原文引文，引用关系必须引用对应资料；无事实片段不能携带整体支持或引用覆盖分。无引用时覆盖为零，联合引用支持不能低于任一单独引用，也不能高于资料整体支持。该证据契约与普通固定检查项在同一次调用返回，后台作业分别保存对话分与证据分。

RAG 单轮作业必须关联本轮成功 responseId，入队时从该回答 RagResponseDetail 重建证据材料并与快照完全比对；不能用同会话其他分支资料替换。逐次结果保存 items/score/ragAssertions/evidence，断言含原文引用依据。暂评结果保留 score，并新增 evidence；正式 RAG 结果使用 dialogue/evidence 两组聚合，逐片段 needsCitation 分歧同样判 judge_unstable，不能被相同维度均分掩盖。任一组 failed/unstable/incomplete 时作业不能为 scored。RAG 生成完成后提交轻评作业，队列异常保留生成结果并通过已有评分提交失败事件告知。

### 5.4 会话分

目标完成 goal 30%、长期信息保持 memory 25%、一致性 consistency 20%、纠错 correction 15%、推进效率 efficiency 10%。按相同检查项公式计算，不平均单轮总分替代会话评价。

每维度记录 opportunities、成功次数及失败轮次。不存在验证机会标不适用；证据缺失标 unknown。正常接受用户修改不算矛盾。会话报告固定 throughTurn，未来续聊不修改旧报告；报告显示回答成功率、评分覆盖率、关键失败轮次、RAG 证据趋势和未解决问题。仅正式且可比的评分版本/覆盖范围可排序；单次暂定评分与不同版本不得混排。

长报告分段执行约定：沿用 conversation_assessments 和 conversation_judge_runs，不另建收费流水。session 作业可固定 batches 数组，每段只包含总快照中逐字一致的来源和固定检查项；检查项必须恰好分配一次、所有原文来源均被至少一段覆盖。三次正式评审分别执行同一组分段；run_index=(评审序号-1)×段数+段序号，每次调用均独立登记、落库和入账。最终先按评审序号合并检查项再计算会话维度，禁止平均分段总分代替检查项公式。某段失败则该次完整评审无效，至少两次完整有效且稳定才可正式出分；中断保留已发生费用，不自动重跑。公开逐次结果标记 reviewIndex/batchIndex，既有单轮一段协议不变。分段同样需原文依据，不以生成摘要替代；单份资料超预算、缺少跨段关系证据时必须显式记录未知覆盖，不能悄悄省略。

报告入口接收 modelConfigId/throughTurn，按会话、分支、截止轮次和版本幂等生成一份正式报告。首版报告按完整原始消息顺序装入有界窗口，每窗口固定五维检查机会，Judge 仅对存在的机会判适用。所有原文至少出现一次；无法容纳单条消息则收费前明确拒绝，不能裁切成不同含义。多个窗口之间的全局目标、记忆与一致性尚无充分联合材料时，增加固定 unknown 检查项，报告明确跨段局部审查并保持综合分为空；不能用原文覆盖率冒充推理关系覆盖率。报告同时固定生成成功率和失败轮次；趋势和逐组机会已接入展示；后续补跨段证据汇总、语义机会定位和问题解决状态追踪后才视为完整会话报告交付。

### 5.5 评审策略与隔离

每回答一次轻评，所有维度一次请求，status=provisional。手动正式复评总计三个独立调用，输入快照、检查项、配置与版本固定；同一模型重复调用不是统计置信区间。至少两次有效，各维度分差 <=2，关键要求/适用状态无冲突时 scored；否则 judge_failed / judge_unstable / incomplete。不无限自动重试收费调用。

会话报告独立三次会话级评审，不自动升级单轮分。Judge 不得与候选配置相同，也不得同供应商同模型；不提供候选品牌；不执行候选或资料中的指令。只输出简短可审计理由，不索取思考过程。

评审从原始消息构建独立证据：要求原文 + 最近原文 + 相关历史片段 + 本轮实际 RAG evidence，不能只看生成摘要。长报告分段检查并保存证据，再汇总；budget 不足则 coverage 不完整，不宣称全量审查。普通没有标准答案时正确性是 Judge 判断，非外部事实核验。

新版本 chat-multiturn-v1 / rag-multiturn-v1。反馈独立展示不改变新版本质量分；旧单轮公式和反馈重算保持原样。

### D. 普通/RAG 执行集成
- 普通自动评分流水线：轮次预留后先以冻结摘要模型提取并版本化保存共享要求，使用 requirements 阶段独立入账，随后将有效要求作为不可信记忆交给各分支。生成完成后按成功回答的原文、分支历史及要求来源建立固定检查项并提交 provisional 作业；response_id 必须属于该轮该模型且答案一致。未启用 Judge 时不创建评分作业。即时投递失败保留 queued 供恢复；评分提交异常通过独立事件报告，不回滚已保存回答。
- 要求提取边界：只读取当前用户原文和已记录要求，不读取当前候选回答。模型返回新增要求的逐字引文、作用范围、关键标记、歧义与替代关系；ID 由服务端生成，不能替代不存在或已失效的要求。歧义指代不得撤销旧要求，也不能标为关键要求；涉及各分支建议的指代需后续按分支解析。空结果代表本轮未提出新要求，不得因此删除旧要求。
- 普通 HTTP 流式契约：POST /conversations/{id}/turns/stream 在返回 200 前推进至 turn_started，完成权限/配置/额度/幂等轮次检查；其后输出 NDJSON，运行故障输出脱敏 stream_error，断连关闭内部生成器。现有 TEXT 的单条问题上限按 UTF-8 65535 字节前置验证（不限制累计会话长度），防止数据库才报错。RAG 会话按持久化模式进入 RAG 协调器，不能退化为普通无检索回答。
- 普通生成协调：先校验并冻结候选/摘要模型运行配置，再原子预留轮次；每分支独立准备输入，生成前登记回答与用量占位，流式 delta 不作为可续聊的完成回答。完整 reply 落库并入账后发 answer_completed，失败分支不污染成功分支。生成期间不运行旧单轮评分；旧任务兼容记录明确排除旧评分统计。新评分由独立后台作业接入。断连取消所有分支并收尾本轮；HTTP 接入和重试/跳过入口另行验证。
- 摘要阶段入账：每个会话轮次/候选分支/尝试/摘要批次拥有唯一 operationKey；调用前锁定会话并检查作者、当前生成轮次、摘要模型、账号及额度，登记 pending；调用后独立事务保存冻结模型计费快照和已知/未知用量并入日累计。重复开始拒绝付费，重复结束不重复入账；生成轮次结束后的已发生调用仍允许收尾。此机制与上下文快照复用结合，避免再次摘要已保存输入。
- 摘要调用契约：旧历史按预算切片，采用有界滚动摘要而非整段一次发送。每次输入包含上次结构化摘要及本批原文；输出 summary/facts，facts 带来源 ID 与逐字片段并校验确实存在，用户要求不能引用模型回答冒充。每次调用执行前/完成后回调用于额度和阶段流水；解析失败也先报告已发生用量，不自动重试。压缩输出超限或无法保留关键信息时失败，由现有上下文预算规则决定回退/终止，不静默截断。
- 历史装配契约：生成入口仅能读取作者自己的固定模型分支、目标轮之前的完整成功问答。来源 ID 使用 `turn:{id}:user` 与 `response:{id}`，保留原文供评分审计；上下文内核再排除历史思考块。重复成功回答视为数据冲突，不能任意选取。生成前持久化 context 快照（消息、来源、哈希、预算估计、摘要），写入时复核目标轮仍在生成；原始任务与回答不被覆盖。
- 恢复规则：复用 Worker 每 60 秒恢复循环，每批至多 20 个 queued 评分重新投递；数据库认领防止重复收费。开始超过四小时的 running 作业（大于 Worker 三小时硬超时）只改 interrupted，并将 pending 调用用量标 unknown，不重跑。恢复入口先检查新表是否存在，未迁移业务库跳过。恢复不会创建新评分，也不会向供应商发送请求。
- 后台分发契约：复用 `rag` 队列，消息只携带 assessmentId，Worker 从数据库获取作者及冻结配置。运行时重新解析启用模型和凭据，核对目标指纹、防止自评，计费参数使用会话快照；配置不一致将未开始作业标为 judge_failed，不调用模型。消息发送失败保留 queued，供后续恢复投递；恢复扫描每 60 秒重投 queued；端到端队列恢复可靠性仍需真实 Redis/Worker 验收。
- 阶段额度入账契约：`record_conversation_usage` 锁定已完成且用量已知的 conversation_usage，按调用登记时间（UTC 转北京时间）归属日期，同事务累加 daily_user_token_usage 并设置 accounted=true；不伪造 response_id 或重复写旧回答日志。未知用量不扣为零、保持待核对。评审每次调用前重新校验用户有效与当天剩余额度；这沿用现有先检查后记实际用量策略，不构成并发 Token 预留。
- 评分作业执行：内部服务只接收服务端构建的 JudgePacket。创建作业锁定会话，operationKey 相同且输入相同返回原作业，输入不同返回 409；queued→running 原子认领后提交事务，再调用模型。每次调用单独持久化判定及原始来源引用、已知/未知用量，正式复评固定三次。重复投递 running/终态作业不得调用供应商；中断转 interrupted，不能自动重跑收费请求。已知阶段用量已接入日额度并设置 accounted=true；未知用量保留 accounted=false。后台分发与端到端验收前不可开放生产入口。
- 评审调用边界：`services/multiturn/judge.py` 接收服务端固定检查项、截至当前轮的原文来源及候选回答；Judge 仅返回检查项 ID、判定、理由和来源 ID/逐字片段。服务端禁止增加/遗漏检查项、改写维度或关键要求，校验片段真实存在后调用确定性评分。JSON 重复键、额外字段和非法档位均拒绝。调用成功但解析失败仍保留 ModelReply 用量；调用异常不伪造零用量、不自动重试。输入预算超限在调用前拒绝。该模块不承担权限、作业调度或持久化，集成时必须由会话服务提供已授权快照。

### E. 前端双工作台与报告

报告面板的请求生命周期：仅列出会话冻结的模型分支；截止轮次以会话全局状态为准，不受当前历史分页影响。提交成功后重新读取服务端分页，不在客户端推算幂等提交产生的总条数。会话切换及卸载取消列表和详情读取，旧提交结果不得写入新会话；待处理报告采用每 3 秒一次、最多 30 次的有界刷新，超出后保留手动刷新入口。未配置评审模型不允许提交报告。验收覆盖固定分支、轮次边界、报告来源与分段标识，并串行执行前端测试和生产构建。

报告统计展示契约：生成成功率使用 successfulResponses/turnCount；原文来源覆盖率使用 report.sourceCoverage，并单独标注不能代表评分覆盖率，评分覆盖率读取正式聚合 result.coverage。opportunityReviews 按三次完整评审分别展示五维的机会、成功、未知、不适用和失败检查项，不累加三次机会。无效评审不显示伪造的零机会。RAG 趋势展示报告创建时冻结的逐轮状态、证据总分与覆盖率，未评分/失败/缺失数据明确保留，不插值、不与会话分求平均，暂定分标明暂定。验收覆盖零分、未知、无效评审、缺失字段和快照时间含义。

失败项追溯契约：Judge 的 source_id/quote 经固定 packet 校验后，服务端保存 evidence_refs（source_id、turn、quote），轮次只能来自快照，不能由 Judge 自报。兼容保留 evidence 文本字段；旧结果没有结构化引用时不从文本猜测轮次。报告逐组保存失败和未知检查项、关键属性、简短原因及原文引用，未知项称为待判断项，不冒充已确认错误；引用轮次标为依据轮次，不能把用户要求出现轮次当作模型失败轮次。详情显示检查项编号及来源轮次原文，可据此审计失败统计。无新表或迁移，继续使用已有 JSON 结果。

跨窗口要求评审增量：服务端依据要求 source_turn、scope 和 retired_at 计算有效范围，为每项要求固定该范围内全部原始问答来源 ID。长报告中该集合能装入独立预算窗口时，单独评审要求，不再因主报告分窗口而强制未知；已标歧义的要求继续未知。要求范围仍超预算或未提供完整范围映射时保持未知并写明限制，不能只挑有利回答或只带要求句。范围映射必须引用总快照内现存来源，每项检查仍仅分配一次。全局目标、长期记忆和一致性的跨窗口联合检查仍单独保留，要求分段通过不等于全局联合判断完成。验收覆盖非相邻来源、退休边界、超预算、歧义保留、来源守恒与幂等快照。

生成恢复的存活前提：普通/RAG 新轮次各启动一个每 60 秒更新的心跳，只有 owner、当前 turn 和 generating 状态均匹配才更新 conversation.updated_at；重复请求不启动心跳，生成结束、断连和卸载取消并等待心跳退出。心跳失败只记录日志，禁止触发重新生成。旧 RAG 创建时间超时扫描在已迁移环境排除 conversation_turns 关联的任务，避免误关长对话；未迁移业务库继续旧逻辑，不查询不存在的新表。心跳、新旧边界、异常轮次原子收尾、用量结算和迟到写入拦截已接入隔离验证；真实 Worker 崩溃演练仍待完成。
